## Verification layers after approval

1. Pure tests for the explicit reporting catalog, date/period arithmetic, amount aggregation, comparison rules, revision canonicalization and typed CSV serialization.
2. Disposable PostgreSQL integration tests through real report routes for tenant/financial scope, pagination, complete-input totals, limits and coordinated revocation/deletion races. Mocks alone do not establish authorization or isolation.
3. Relevant predecessor regressions: 015 R001/R005/R008, 014 R010, 010 R011, ledger adjustment behavior, connector coverage and privacy/access suites. Extend this selection when actual code changes touch more services.
4. Before claiming the completed implementation ready, run the repository's required backend/contract checks and applicable broader suite, update the OpenAPI snapshot and review its diff. Run tracker/browser tests if shared behavior changes or the applicable repository gate requires them; avoid repeating unrelated suites for this documentation-only preparation.

Record exact commits, commands, environment, pass/fail/skip counts, limitations and measured bounds in implementation evidence. Do not substitute the earlier Spec 015 result for tests of new reporting code. Full 016 AC5 additionally requires retained artifact/deletion tests in 016-C; V03/V13/V17 do not close that obligation.
