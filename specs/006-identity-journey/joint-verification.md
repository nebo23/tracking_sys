## Evidence and closure rules

- Record test names, commands, exact code head, database version/role, results and intentional exclusions per phase. A planned case is never a passed case.
- A reproduction or equivalent failing test must precede each claimed deferred-finding closure. For not-yet-implemented behavior, a failing acceptance test followed by passing implementation is sufficient; do not claim it failed on the old application if the API did not exist.
- Run backend unit/contract, all integration modules, the existing three browser journeys and tracker unit/browser suites after cross-cutting implementation. Run formatting/lint, dependency consistency, OpenAPI compatibility and migration/grant checks. Any expected contract extension is documented; unexplained old-contract changes block completion.
- Check deletion, consent, live authorization and report release with concurrent database transactions, not only mocks or function call assertions.
- Preserve D-063: 012/013 remain deferred. Record pending production 008 persistence, 016-B/C, provider checks, native rollout, CI and deployment accurately.
